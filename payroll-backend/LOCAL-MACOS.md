# macOS 本地单机版

本模式只监听 `127.0.0.1:3001`，同一局域网内的其他电脑也无法访问。适合一名 HR 先在固定 Mac 上使用。

## 一键安装

```bash
cd payroll-backend
./deploy/install-local-macos.sh
```

安装器会：

- 构建 React 前端并安装后端生产依赖；
- 将程序版本安装到 `~/Library/Application Support/AI Payroll/releases/`；
- 将数据库和上传文件独立保存在 `~/Library/Application Support/AI Payroll/data/`；
- 创建正式空库和随机管理员密码，不导入演示员工；
- 注册登录自动启动任务 `com.aipayroll.local`；
- 注册每天 02:30 自动备份任务 `com.aipayroll.backup`；
- 在 `~/Library/Application Support/AI Payroll Backups/` 生成并校验首次备份；
- 在桌面创建“HR系统备份”入口，方便查看备份文件；
- 在桌面创建“打开HR系统.command”。

## 日常检查

### 简历和面试记录

- 简历库详情支持“删除候选人”，从日常列表移除后可在“已删除”中恢复；原始附件、个人资料、面试和流转记录、飞书唯一标识随归档保留。已关联员工、审批或猎头费用的档案继续受保护。删除本地档案不会删除飞书记录。
- 淘汰人选时，已发生但未补录完成状态的面试会记为完成，当前轮次尚无结论时记为未通过；已有面评保留，早期轮次不虚构失败结论。未来未进行的安排仍为取消。

- 员工档案、候选人详情均支持上传并解析 `.txt`、`.md`、`.docx`、`.pdf`、`.xlsx`、`.xls` 简历（每份不超过 10MB）。Excel 按工作表提取单元格文字；不执行公式或宏，图片中的文字暂不识别。加密工作簿需先解密另存。
- 同一人选或员工可保留多份简历附件，每次支持选择 1–10 个文件；新上传文件追加保存，不覆盖旧文件。解析窗口先选择具体文件，再选择本地模型或基础提取。每个文件独立保存解析结果，预览明确显示来源，核对后只应用所选文件。删除单份附件保留其他文件及已确认的个人资料；录用关联员工时全部附件独立复制。
- v29 将原有候选人单文件简历迁入 `candidate_resumes`，保留原始文件路径、正文、解析结果和已确认资料，并补记来源文件。升级前自动备份；备份包仍包含数据库及完整 uploads 目录，因此多份附件会一起备份。
- 简历库列表显示人选状态与最近面试；详情中的“查看 / 编辑全部面评”进入同一候选人的面试记录。面试列表点击候选人姓名可返回详情，两处共用同一份记录。
- “简历库”提供直接上传简历建档、手动输入两种方式；每次建档、资料更新、面试安排、轮次流转、录用与关联员工都保留操作人和时间记录。历史档案只补当前状态基线，不推测此前未记录的流转。
- 简历解析完成后，点击对应文件的「查看结果 → 核对并更新个人信息」，可校正全部个人字段、教育和工作经历，再点「确认更新个人信息与岗位」保存。已保存资料会直接出现在详情的个人信息区域，刷新后保留；新识别的联系方式优先，缺失值保留原资料。未确认的解析结果会明确标示「尚未更新个人信息」。
- 员工简历预览支持「校正识别内容 → 确认写入个人信息」，同一学校/任职记录可以更新，重复应用不重复新增。需要清理旧的错误经历时，可明确勾选用本次结果替换；应用前后完整资料保存在 `resume_apply_history` 中。已核对的候选人完整资料会在关联新增员工时一并带入。
- v28 升级会在数据库事务中修复历史简历文件名的 UTF-8/Latin-1 乱码，实际附件路径和文件内容不变；升级前由安装器创建并校验备份。
- 在简历解析结果的「核对并更新个人信息」页面，未关联岗位的人选会自动由本机模型匹配在招需求，显示最多三个建议、匹配理由及简历原文依据。只有一个方向直接对应的岗位时会预选；多项相近或信息不足时由 HR 选择。点击「确认更新个人信息与岗位」一并保存，并记录关联岗位名称。已有岗位会保留，可点匹配按钮检查其他选择；职业资料调整后可以重新匹配。
- 匹配只使用专业技能、专业方向和任职职责，姓名、性别、年龄、联系方式等不进入匹配模型。关闭、草稿、取消及名额已满的需求不参与新匹配；保存时再次检查岗位状态。已录用、已入职或已有待审批/已批准 Offer 的人选不能直接改换关联岗位。
- 安排面试后显示“待面试”，开始后显示“第 N 轮面试中”；面评完成后由 HR 人工推进 Offer 和录用。Offer 审批通过并确认录用后，可从“员工档案 → 新增员工 → 关联已录用人选”建档，简历独立复制到员工档案；同一人选不可重复建档，建档后支持继续上传和更新信息。
- 月度“待面试人数”只统计计划日期属于所选月份、状态仍为待面试的安排，按人去重；与面评结论“待定”区分。历史月份依据流转快照还原月末待面试状态，已取消的安排不计入。
- 招聘总览的月度面试统计按上海日期、实际面试日期统计，同一人同月只计一次，以当月最后面试日期、同日最高轮次及最后记录判断结果。“强烈推荐 / 推荐录用”为通过，待定也计入面试人数；通过率为通过人数除以面试人数，无面试时显示“—”。未来日期记录不计入累计，历史月份可切换查看，修改历史面评会同步更新该月统计。

### 服务与备份

```bash
curl -fsS http://127.0.0.1:3001/api/health
launchctl print gui/$(id -u)/com.aipayroll.local
launchctl print gui/$(id -u)/com.aipayroll.backup
```

立即手工备份：

```bash
"$HOME/Library/Application Support/AI Payroll/current/backend/deploy/backup-macos.sh"
```

每个备份由 `.tar.gz` 和同名 `.sha256` 组成。系统备份数据库前会短暂停止本地服务，完成数据库与附件快照后马上恢复服务，再进行压缩和校验。默认保留 30 天。

## 数据与恢复

备份包内包含：

- `payload/payroll.db`：全部系统数据和账号；
- `payload/uploads/`：员工及候选人简历附件；
- `payload/city-policies.json`：若配置过城市政策文件；
- `payload/job-catalog.json`：若配置过本机私有岗位词典；
- `payload/feishu-config.json`：若连接过飞书，含应用凭证，按私有人事数据保护并随数据库一同恢复；
- `payload/private-tools/`：若存放过本机私有数据导入工具；
- `payload/MANIFEST.txt`：创建时间和数据库 SHA-256。

恢复前必须退出系统并停止服务，然后先校验 `.sha256`，解压到临时目录，对数据库执行 `PRAGMA quick_check`，最后替换 data 目录。替换属于覆盖性操作，应由管理员明确确认后执行。

## 安全边界

- 本地 HTTP 下配置 `COOKIE_SECURE=0`，但只允许本机回环地址访问；不要改成 `0.0.0.0`。
- 外部 Copilot 与简历 LLM 默认关闭；需要使用时应先完成数据合规评估。
- 建议开启 Mac 的 FileVault 和自动锁屏。
- 不要把正在使用的 `payroll.db` 放进 iCloud、Dropbox 或 OneDrive；只同步已经生成完毕的 `.tar.gz` 与 `.sha256` 备份。
- 公司专属岗位词典放在 `data/job-catalog.json`，由 `JOB_CATALOG_FILE` 指定；不会进入源代码、公开前端包或 Git。公开版本使用通用岗位默认值，HR 登录后再读取本机词典。公司一次性数据导入工具可放在数据目录的 `private-tools/`，不放入源代码。
- 本机硬盘损坏时，本机数据和本地备份可能同时丢失。正式承载数据前，建议再把备份目录纳入加密移动硬盘或受控云盘备份。

## 本地 Qwen 简历解析

本机已下载 LM Studio 的 `qwen/qwen3-vl-8b` 后，可启用安装：

```bash
PAYROLL_LOCAL_RESUME_MODEL=true ./deploy/install-local-macos.sh
```

安装器会注册 `com.aipayroll.resume-model`，登录 Mac 时启动 LM Studio 本地接口（仅 `127.0.0.1:1234`）并加载模型。桌面「打开HR系统」也会启动此任务。模型使用 16384 上下文、单份简历依次处理，约占 5.4 GiB 模型内存，生成期间还需额外内存。后续升级沿用本地模型配置。

在简历库或员工档案的简历区域，点击「选择解析方式 → 开始本地模型解析」。结果显示模型、用时、教育及工作经历，核对后再编辑人选或应用员工档案。模型失败会明确报错并保留原有结果，不会静默切换规则或调用外部服务。

支持含文字的 PDF、DOCX、TXT/MD、XLSX/XLS；扫描 PDF 和图片尚未接入 OCR。长简历分段处理，文字总量上限 24000 字符，超过时提示拆分；每段超时默认 180 秒。上传新候选人仍先保存附件并做基础提取，建档后可选择本地模型重新解析。

模型不可用时，打开 LM Studio 并在 HR 页面点击「刷新状态」。必要时启动：

```bash
launchctl kickstart gui/$(id -u)/com.aipayroll.resume-model
```

本地解析独立于外部 LLM 配置；`COPILOT_EXTERNAL_LLM` 和 `RESUME_EXTERNAL_LLM` 仍为 `false`。后端只接受回环 IP 的模型地址，禁用重定向，简历不会经此解析流程发往远程地址。
