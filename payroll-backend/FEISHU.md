# 飞书多维表格简历库

本地系统保存完整档案与原始简历。HR 从「简历库 → 同步到飞书」选择人选、资料字段和附件，预览后手动发送到一个指定的飞书数据表。此功能为单向同步，不会把飞书修改写回本地，也不会定时自动上传简历。

## 首次连接

1. 在飞书新建一个空白多维表格，命名为「简历库」。不要选择其他数据源的自动同步表。复制网址，例如 `https://example.feishu.cn/base/BASE_TOKEN?table=tblTABLE_ID`，也支持 `https://example.feishu.cn/wiki/WIKI_NODE_TOKEN`。不带 `table` 参数时可在本地系统读取列表后选择。
2. 由企业管理员在 [飞书开放平台](https://open.feishu.cn/app) 创建企业自建应用，取得 App ID 和 App Secret。不要把密钥发到聊天、提交到 Git，或写进前端代码。
3. 在应用身份权限中开通多维表格记录的查询、新增、更新、字段的查看和新增。上传简历附件还需「上传图片和附件到云文档中」（`docs:document.media:upload`）；只有多维表格的细分读写权限不包含此权限。知识库链接还须开通知识库节点读取权限，让应用能访问该节点。发布应用并由管理员启用。文档权限与应用 API 权限需要同时具备。
4. 在飞书表格的协作者中添加该应用，授予可管理权限。开启高级权限的表格也须为应用配置完整可见、可管理的范围，避免搜索接口返回不可见的空结果。
5. 用本地系统管理员账号进入「连接配置 / 建表指引」，填写目标链接及应用凭证，点击「读取数据表」。系统会把知识库节点解析为真实多维表格标识，分页读取表名；多张表时必须明确选择，不能静默选择第一张。单表可预选。保存配置、检查连接，再点击「补齐标准字段」。该操作会在指定表中添加缺少的列，不发送人选数据、不删除原有内容。同名列类型有冲突时会停止，由管理员先调整。链接或凭证改变后须重新读取，解析结果有效期为 10 分钟。
6. HR 选择少量测试人选和文件，核对发送预览，再确认同步。在飞书核对成功后可分批使用。

## 字段与行为

“期望年薪”使用独立多行文本列，显示明确的人民币元/年金额；与“期望月薪”分别选择、分别同步。系统不从年薪折算月薪，也不将年薪用于基于月薪的猎头费用估算。

标准文本列：本地人选标识、姓名、联系电话、邮箱、应聘岗位、期望月薪、招聘状态、来源渠道、建档日期、技能、教育经历、工作经历、本地同步时间。以上均为「多行文本」，电话号码不会丢失前导零；「简历附件」使用附件类型。可在飞书另加负责人、跟进备注等协作列。

- 每批最多 20 位人选、50 份附件、附件总量 100MB，单文件不超过 10MB。附件默认不选，可逐份勾选。
- 个人技能、教育和工作经历只读取已保存的个人资料，不读取未确认的模型结果。姓名和联系方式使用本地已建档的值，发送前应核对预览。
- 不提供出生日期、性别、婚姻、住址、证件、员工薪酬和面评等字段的同步。原始简历自身可能含有这些内容，发送附件前请自行核对。
- 预览有效期 10 分钟，绑定登录用户、配置及所选资料/文件内容。配置、资料或附件改变后须重新预览。
- 用随机且持久的本地人选标识查询飞书记录，重复同步更新原记录，不按姓名合并。不要手工修改、清空或复制「本地人选标识」列。不同本地人选即使同名，也会分别保存。
- 已同步记录若被删除或不可见，将停止该人选的同步，避免未经核对重新新增。未成功确认的新建请求保留相同幂等请求号，重试前先查询标识。
- 更新时只覆盖所选字段，所选空字段会清空飞书对应列；未选字段及飞书其他列保留。上传的附件与飞书已有附件合并，不删除已有文件。本地删除资料或附件不会删除飞书副本。
- 每位人选独立报告成功或失败，部分失败时可仅重试失败项。附件已上传但记录保存失败时，重试会复用该 Base 内的附件标识。网络中断且未收到上传确认时，飞书素材区可能留有未关联素材，但不会因此重复创建人选记录。
- 应用凭证过期、权限变更、飞书限流或附件令牌失效会提示失败；先修复相应问题再重试。没有自动重试写入或后台自动删除。
- 连接检查和预览会刷新授权并检查附件上传范围，已知缺少上传权限时会阻止包含附件的批次；不选附件仍可同步个人资料。若接口返回 99991672，清除旧授权缓存、停止继续请求本批其他人选，并提示缺少权限，避免重复出现整批失败。补充权限并发布后重新预览即可，无需重填密钥。

## 配置、备份与迁移

App Secret 只保存在服务器数据目录的 `feishu-config.json`，权限 0600。可用 `FEISHU_CONFIG_FILE` 设置其他私有路径。读取配置接口不会回传密钥。只有本地管理员可修改配置和添加远端标准字段，HR 可预览和发送，财务及员工账号不可访问此集成。

Mac 安装升级保留数据目录中的该文件。每日自动备份包含此配置、数据库里的同步标识与原始附件，备份文件权限 0600。恢复时须同时还原 `payroll.db`、`uploads/` 和 `feishu-config.json` 到私有数据目录，避免丢失人选与飞书的对应关系。备份中含应用密钥，应按人事数据同等保护，不可提交到公开仓库。克隆恢复的数据若用于独立系统，应连接另一个数据表，以免共同更新同一批飞书记录。

仅由这台 Mac 主动访问飞书 HTTPS 接口，不需要开放入站端口或公网部署。未配置时可本地预览，不能发送；实际接入尚需真实飞书应用和目标表格验收。

## 官方接口依据

- [获取企业自建应用访问凭证](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)：服务端凭证缓存，使用返回的有效期。
- [飞书官方 Node SDK 的多维表格接口定义](https://github.com/larksuite/node-sdk/blob/main/code-gen/projects/bitable.ts)：字段类型、查询过滤、记录创建幂等号、记录更新。
- [飞书官方 Node SDK 的素材接口定义](https://github.com/larksuite/node-sdk/blob/main/code-gen/projects/drive.ts)：`bitable_file`、Base 所属标识及 multipart 上传。
- [多维表格常见问题](https://open.feishu.cn/document/docs/bitable-v1/faq?lang=zh-CN)：附件必须先上传到对应 Base，再写入记录附件字段。
- [获取知识空间节点信息](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/get_node)、[列出数据表](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/list)：知识库链接解析及目标数据表选择。
